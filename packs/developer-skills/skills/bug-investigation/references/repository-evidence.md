# Repository evidence

Use `scripts/bug_investigation.py` with Python 3.11+ and Git. It is read-only except `project set`, which writes only the chosen project registry. It does not infer causes or generate report prose. Run it from the application or project workspace, not the installed skill directory.

`project set --project ALIAS NAME=PATH [NAME=PATH ...]` and `project list` use the same `schema_version: 1` / `projects` format and location as `change-report`: the invoking Git repository's `change-report/projects.json` under Git metadata. `CHANGE_REPORT_HOME` can select that existing registry directory. For a parent folder without Git, pass `--config PATH` to an explicit JSON file using the same schema. Relative member paths resolve from the registry file's parent; absolute external paths are supported. A project member name is a label, not proof of a role or project boundary. The helper preserves other aliases and refuses malformed, duplicate, or empty member definitions. `project set` changes registry only, never application files.

`repos --project ALIAS` returns the chosen members, independent Git roots, branch names and availability in JSON. It reports missing members as incomplete read-only coverage. Add `--require-complete` before a cross-repository fix; a failed selection must not become a partial fix. Without `--project`, the current Git repository is the target. `diff --repo PATH` returns current worktree change status and exact old/new line ranges relative to HEAD, including relevant untracked files, for source-table assistance. It omits obvious sensitive or generated paths and reports their count. It is not a task baseline or proof that a change belongs to this investigation. For committed fixes, use the relevant commit or known baseline separately; read the changed code and tests. Do not report a diff entry as a fix without establishing attribution and purpose.

`parse -- <chat arguments>` validates option combinations after the agent removes `$bug-investigation` or `/bug-investigation`; it cannot resolve a missing verification subject. Quoting and tokenization are done by the calling shell, so pass individual arguments safely rather than building an interpolated command. Paths with spaces and Unicode are accepted. The helper does not read whole-machine paths, scan unselected repositories, mutate application files, or run tests.

`validate --file PATH.md [--detailed] [--allow-hashes]` checks report structure only. Use `--allow-hashes` only when hashes were explicitly requested. It cannot verify causes, source attribution, role access, counts, or whether checks passed; the agent must compare those claims with actual evidence. It reads the named file without modifying it.
